Rebuild the KUBS DT keynote deck for session $1.

From the socrates repo root:

```
python3 projects/kubs_dt/pipeline.py slides --session $1
```

The deck's text, slide by slide, lives in `KUBS DT Sn/KUBS DT WS2026 Enn.md` in Google Drive — `## n · type · title` sections for the cover (`title`), the numbered content slides (`rows`), the two-column comparison (`opposition`), the navy divider (`screen`), and hand-made or rendered slides (`image` — the command writes nothing for them). The command takes a uniquely named copy of the deck, writes every slide's text and notes from the md, recomputes every row's colour bar against the rendered text, verifies bar and text line up within 2 px, and overwrites `KUBS DT Sn/KUBS DT WS2026 Enn.key`; the previous deck stays in the stage folder as a backup. The read pass is cached and slim: an item's font, size and position come in one Apple event (the item's text is not read — the planner never used it), and the whole read is skipped when the deck's files are unchanged since its last read (`~/.cache/socrates/kubs_deck_Sn.json`, refreshed by the command's own install; a Keynote save changes the files, so an edited deck is read again). After the bar verify a layout pass measures every `rows` slide and prints its numbers (title anchor, headline tops, grey offsets, gaps, air); the deck is installed either way and a flag exits 2 — row spacing and title alignment are hand passes, the check only names them. Measured on E02, 7 slides (before the cache): read 28 s, apply+save+export 20 s, measure 0.6 s, bars+save+export 12 s, verify 0.7 s. Measured 2026-10-02 on E05, 5 slides, cached read: read 0.0 s, apply+save+export 9.4-9.9 s, measure ~1.0 s, bars+save+export 8.9-14.1 s, verify 0.8 s, layout 1.2 s.

- **The md is the only source of slide text.** Never rebuild a slide's text from the deck or from a render. If a deck has no md yet, write the md from the deck's current text once (byte-exact, including the cover's line-separator character), then edit only the md.
- **Homework slides take session 1's blue band** (#384894, the `blueband-3624.png` asset inside the E01 deck) instead of the session colour — the standing rule for every deck. The band swap is not wired into the command yet: a slide marked `· homework` makes the command stop and say so.
- **A deck open in Keynote refuses the run — close its window first.** Keynote autosave fails while its file is being rewritten ("the file has been changed by another application"), and the alert that follows hangs every further osascript call, `close` included (force-quit Keynote to recover; only then fix the cause).
- **Bar geometry comes from a render, not from the boxes.** The command renders the deck, measures each row's ink span, and places the bar to cover it exactly: bar box y = ink top + 3, height = ink span − 5; the drawn bar bleeds 3 px above and 2 px below its box at 1920x1080. Never hand-place a bar — re-run the command.
- **The layout pass reads the render.** Every `rows` slide is measured after the bar verify: title ink anchor and column, headline ink tops, each grey sub-line's offset (1.3 x the headline size), the gaps (0.055-0.135 H, even within 24 px), the air under the last line (>= 0.075 H). Flags print with the pixel values and the command exits 2 with the deck installed. Calibrated 2026-10-02 against the signed-off renders (E02 pages 3-5, E05/E08 pages 3-4, zero flags). The positions are not repaired here — row spacing is a hand pass and Keynote's script cannot set title alignment; the check names the deviation so it is not found by eye.
- **Structure changes are not the command's job.** If the md and the deck disagree on slide count, row count or pairs, it stops and names the slide; add or remove the row in Keynote first, then re-run. A slide you insert by hand (the course chart, an imported render) is mirrored in the md as an `image` section at the deck's position — the command counts it and leaves it untouched; without the section the run stops on the count before writing anything.
- The command prints its measured seconds per step, the per-row bar/text offsets, and leaves a backup of the previous deck in the stage folder. Relay those numbers.
- If osascript times out, Keynote is showing a modal alert: look at its screen, dismiss it, close the stray `slides_build_*` document, and run again. Never overwrite a `.key` file while Keynote has it open.
- If a run fails with an execution error instead of a timeout (2026-10-09: the read pass could race the just-opened copy and die on "Invalid index"), the command now closes its build copy before the error surfaces, and the generated scripts wait for the copy's slide count to settle before reading. Before retrying, still check `every document` and close any stray `slides_build_*` — restoring the state comes before looking for the cause.
- An `open` can be refused at the file layer and leave a file panel standing (2026-10-09: the app's sandbox refused a path, `Could not open() the item: Operation not permitted` in its log; the panel is invisible to System Events and blocks every later open — kubs.md carries the incident and the ghost panel class). On the first refusal: look at the screen, clear the panel (`activate` + Escape), verify the app is clean, and stop — one open mechanism per run, never a chain of retries over a standing dialog. When a one-off edit of a deck is needed outside this command, work on the document Chaehan has open; never hand-roll an open of a stage copy.
