# KUBS deck passes

Every deck defect that recurred had one shape: a pass re-derived something the deck already fixed - a box, an inset, a construction, a spec's scope - and no check could contradict it. This skill is the ordered pass; the values live in one file and the checks in one command.

The three artifacts this skill runs on:

- `projects/kubs_dt/deck_reference.json` - the deck's measured reference (the values). Read it before creating or replacing any element.
- `projects/kubs_dt/deckcheck.py`, wrapped as `pipeline.py deckcheck --session N` - the differential checks.
- `agentkit/rebuild_defects.md` - the failure classes with their instances and the user's words; read it when a report smells like a repeat.

## Step 0 - the preflight (before any write; its answers go in the report)

1. **What class does the instruction govern?** A spec on one instance, a class-wide spec, a new element, a removal. Enumerate the instances before touching anything. "All pasted slides on white" means every page whose background is not the theme's; "the Annex is optional" means every carrier that lists the reading. State the class and the count in your report, and sweep all of it in this pass (rule 136).
2. **What must stay?** List the artifact's standing requirements: the page backgrounds, the band-title anchor, the overview chart's session marks, the divider boxes, the page numbering. A new instruction constrains these; it replaces one only when it says so. Open a sibling deck (E06 to E08) and see what a valid instance looks like before deciding (rule 135).
3. **Does the element already exist as a finished asset?** Search the record (`memory/kubs.md`), the session's `_assets/`, `KUBS DT Course Design/` (including `chart_v9/`), and the other session decks. A finished asset is used whole; assembling one from another instance's pixels leaves seams - the 2026-10-09 cell ring carried E06's row strokes and overhung the rounded rectangle (rule 134). And a finished asset is only as finished as the pass that made it: an asset that came out of a renderer (HTML/CSS, a template, a foreign deck) is opened and read at magnification before it is reused - the arrows in this family were CSS border triangles whose heads the renderer halved, and they were placed by size and never looked at (class 8).
4. **Who else is writing these files?** The user runs several sessions over one folder set. Before any write: `openchamber` `session.list` scoped to the directory (a busy sibling), the stage's fresh files, the deck's mtime. A text carrier that moved under you is still yours to edit - re-read the changed lines (RULES.md 141); the deck has one writer - if a sibling pass owns it, park the deck step or hand it to the owner, and the md/script sweep still lands.

## Step 1 - the values (never invent geometry)

Read `deck_reference.json`. The essentials:

| Element | Value |
| --- | --- |
| Band and title | band image (0,12) 1920x112, the IMAGE ALONE - no shape behind it; title box (38,34) 1859x73; the deck's titles share one column within 10 px (E05 measured x 38-40), ink top at y 44 |
| Overview page (slide 2) | one image: the session's `chart_v9/chart_S<n>_v9.png` composited onto a 1920x1080 white sheet, placed at (0,0); the chart itself sits at (121,0) |
| Chart marks | green (62,141,39), inset 2 px, stroke 12 px, radius 34; the session's week row and, inside it, the session's own cell |
| Figure slot | 1662 px wide at x 129 (Fig 2.4 page y 137 h 930; the tip page y 222 h 759) |
| Box format (diagrams, figures) | `figure_box_format`: a standard shape contains its text; every text centred in its box, each box's stack centred vertically; line-broken box-like sizes; per-semantic colours; every box its own group inside its family group |
| Dividers | title box (111,399) Georgia-Bold 108; subtext box (115,576) 1325x184 |

A page whose title was re-created, whose figure was redrawn, or whose chart was swapped is where these values get violated.

**The band is the image alone, and a copied page is not a reference.** A page duplicated from another page brings that page's objects along: the deck family's older banded pages carry a band SHAPE at the same (0,12) 1920x112 rect, whose 2 px red outline (#982B15) is hidden by the band image except for its outer half - a full-width hairline at y 11 and y 124-125 - and which shades the page around the band. It is visible whenever the image sits on the shape, on a blue band as on a red one. Where the band came from a duplicate, build it from this file and delete the shape, and check the page's object dump (a banded page carries the image and the deck's hidden 64 pt title copies, no shape at (0,12) 1920x112). **Identity, not position, decides the removal:** on E01's banded pages the band IS the shape - its blue fill is the band and the red outline is its border - and deleting it would delete the band; those take the opposite fix, the band image laid over the shape with the title re-created above. Measured 2026-10-12: 17 pages carry the hairline. Ten were fixed by deletion that day (E02 3-5, E03 61, E06 5-6, E07 3-4, E08 3-4). Six are E01 4, 5, 6, 7, 11, 20 (band-is-the-shape) and one is E02 6 (the hairline is baked into a pasted full-page render); both closed on 2026-10-13 by a build - the recipes and their measured numbers are `band.build_recipe` and `band.render_patch`, and the two traps they name are that a created text item lands centred in the default style (never at index count-1, where a template placeholder accepts text, font and colour but ignores geometry) and that a created title overflows its box by wrapping, not by shrinking. Four pages carry the object with nothing visible (E01 9-10, E03 62-63). E04 and E05 are clean, E05 since its nine shapes were deleted on 2026-10-09. The `band.construction`, `band.defect_signature` and `band.leftover_shape_instances_2026_10_12` fields carry the values.

## Step 2 - the build

- Work on a build copy in the stage; install with Keynote closed (rule 88). Never write a file Keynote holds open.
- **A rebuild replaces what it owns, never the page.** Read the page's own object list from the app first - classes, sizes, groups - and delete only the objects being replaced, keyed on their exact identity (the size that stood there, the element this pass owns), leaving everything else alone: the band, the title, the user's groups, his hand-set sizes and his moves. Two things this protects, both measured on 2026-10-18: his two grouped 3x3 drawing grids on E08 page 7 - an earlier version of the same build deleted every top-level image and re-added the whole page, which left 18 duplicate drawing cells beside his groups at the same coordinates, a doubling no export can show - and his own portrait frame on page 5 (209x252, which the rebuild had reset to the script's 440x379). Read `count of iWork items` before the deletes, then guard the count after the deletes and again after the inserts: the run stops without saving when either is off.
- **A string-only change** (text that already exists on slides; no new element, no geometry) rides the ops path, not `/slides`: stage copy, `AS_SLIDES_READ` dump, an ops TSV (`txt <slide> <scope> <k> <value>`), `AS_SLIDES_APPLY`, a before/after export diff (only the touched pages may differ), `deckcheck`, byte-checked install. `/slides` runs only when the md is the deck's live source; with hand edits beyond the md it stays parked. Two traps from the 2026-10-11 pass: the stage copy's name must carry the deck's stem (the export finds the document by name prefix), and the read leaves its copy open - close it before `deckcheck`, whose own open fails on it. The full recipe with its driver pattern is in `memory/kubs.md` (Tooling, the two-string pass bullet).
- A pass that only reads works against Chaehan's open document directly - no `open`, no `close`, no save in the script (a hand-rolled open is the abandoned 2026-10-09 class; a `close` of a document the pass did not open is the 2026-10-03 class), and it proves no-touch by the file's mtime before and after - an md5 proves nothing while he edits. Fills, strokes and builds read nowhere; those come from the exported page's pixels (2026-10-10).
- A slide's page carries its own full 1920x1080 white background; the theme is never relied on, and the exported page is the test (rule 133).
- **A page composed as an image carries the deck's band geometry, not its own.** A tile or a rendered sheet that includes the band is on the page exactly as a native band is, and `deckcheck` measures ink: the band occupies 1920x112 px at y 12 (the page above it #F6F8FC) and the title's white ink starts at x 36-46 / y 44-45 - read `deck_reference.json` (`band.title_ink_top`, `title_ink_left_min/max`, `title_box`) before drawing one. 2026-10-16, E08: the four rebuilt story tiles drew their band at the page's top edge with the title ink at x 124 / y 33 and came back as four `band` failures and a 36 px column spread; rebuilt to the anchor they measure x 37 / y 44 and the check passes (spread 1 px). A chip of the agent's own numbering does not belong in the band either - the deck numbers its own pages.
- **A recap page follows the covered sessions' own running order, read off their scripts.** The story slides that recap the semester (E08 4-8) chain the course's blocks in the order the sessions ran them; that order is not what the decks' pages suggest, and a page that *depicts* a step is no evidence that it came next. Before composing a chain, read the scripts of the sessions it covers - each states its blocks in order - and check the session memory. 2026-10-17, E08: the sprint chain ran book -> test early -> design challenge -> the teams' visualizations because those pages were at hand, while S3's own card 8 hands the teams off to "find experts/expert proxies/users" and the S4 script opens on the interviews ("Yesterday you interviewed; this produced How-Might-We question"); the fourth card is the interviews (E03 29) and the visualization, which came after them, has its own page built from the TA's two drawing posters in the S4 folder plus five of the teams' walls.
- Keynote facts that bite (from the deck's log): `make new image` must sit inside `tell slide N` (`at slide N` fails -10000); reading `position` inside a `tell slide` block throws a `sipo` coercion error (-1700), so compute the arithmetic in Python, set positions last, and verify from the export; paragraph alignment is not scriptable, so a centred title is aligned by its box; a new image appends last in the enumeration.
- When an element's text or construction comes from a source (a book figure, a paper), the source supplies the content only. Grouping, geometry and construction come from the deck - the slide's own title teaches the structure it wants (rule 134; the tip figure's INTERPRETATIONS header was the counterexample).
- A new element the user will edit or animate later - a diagram, a row of boxes, a table - is built from the slide's own objects (shapes, text items, the deck's own fonts), never rasterised: a render is right only for content that is itself a render (a book figure, a photo). **A page that arranges photographs and figures is a composition, not artwork** (2026-10-17, E08 5-9: five HTML tiles rendered to one PNG each, installed one page per image, every pixel check green - "the images should be pasted as image, not the whole slide as image, so i can resize each element"). The unit is the element: the band is the band image, the title and captions are live text, each photograph, drawing cell, card and arrow is its own object. A render pipeline whose output is a page-sized PNG is the flattening, chosen at the first step. Shape fill, stroke and corner radius are not scriptable (probed 2026-10-10: `background color` fails at runtime), so a created box carries the theme's default look - that styling remainder is the user's hand pass, named in the report, never traded for a flattened image (rule 104; `rebuild_defects.md` class 6). The settled look for this chart family - per-semantic colours, semantic groups with a centre-out build, line-broken boxes, middle-aligned texts, all hand-set - is the `figure_box_format` block in `deck_reference.json` (Step 1): read that block and the live page's construction before writing a box, and measure each text's ink centre against its box centre from the export (within 8 px; each box's content stack within 12 px) - the numbers go in the report (2026-10-12: "you forgot many design elements i specified in that slide of e05, like all middle aligned"). Captions are centred by measurement, not by the script: `alignment` does not take on a created text item, so a caption's box is placed, the export measured, and the box shifted by the ink centre's delta (E08 5, 2026-10-17: 433 and 1640 on their books' axes).

## Step 3 - the gate (before installing)

1. Run `mamba run -n socrates python3 projects/kubs_dt/pipeline.py deckcheck --session N`. It exports the deck and checks: every page fully opaque; the band titles' column (one column per deck, spread <= 10 px; E05 measures x 38-40) with their ink top at y 44; no stroke row outside the band image (the leftover band shape); no page whose content is one full-page image (`flat`, read from the app's own object list - the reference's `flatten` block lists the pages that are one image by design: the session's overview chart and the pasted foreign pages E02 6 / E03 4-5); and the session's chart marks against the session's own chart file. Exit 2 means do not install; report the flagged lines. A `flat` flag is a page to rebuild from its elements (rule 104), never a page to re-render.
2. Look at every changed page, magnified at the changed region - not fitted. A fitted view hid a 6 px overhang while three measurements passed (rule 137).
3. Compare each changed page against the page it copies (the reference instance), not against your intent. "It looks right" is not a check; "its ink sits at the same coordinates as the tip page's" is.
4. An install into an EXISTING deck (slides added to a deck that has its own pages) exports the WHOLE deck before the write and compares every page after it: the added pages against their tiles, the rest against that baseline. Keynote's `save` writes the whole document, and an object outside the range you touched can be re-linked by it and appear changed — 2026-10-16, E08: the seven story slides landed byte-exact while the same save surfaced a stock illustration that covered a screenshot on page 12 (`rebuild_defects.md` class 7). A page you did not touch is not a page the save did not touch.

## Step 4 - install and record

Backup to the stage, quit Keynote, copy the build to the session folder, reopen, and re-export to confirm. A script that drives the app writes one log line per phase (open, delete, insert, save, export, close), so a hung Apple event reads as a stop rather than as silence - on 2026-10-16 an install sat ten minutes with an empty log and the deck not yet open, and nothing in the run distinguished "waiting for an 8 MB open" from "wedged".

**An install that replaces pages counts the pages it removes off the deck it edits, and guards the count before it saves.** The delete position is fixed (page 4) and the block's length changes between passes, so a count taken from the new page set takes the first page *after* the block with it. 2026-10-17, E08: `install_into_e08.applescript` was handed `nOld 5` for a deck whose story was four pages, deleted the four story pages and then the Yes-and rows page ("opened: 9 slides / deleted, now 4 / inserted, now 9"), and saved a deck a page short; the repair that duplicated the last page doubled the wrong one. Read the deck's own count first, then stop without saving when the count after the deletes, or after the inserts, is not the expected number - both guards sit in the script that pass wrote, and the log's counts are read against the expectation before anything else is done.

**The app's state is checked after every Keynote run, and a dialog is cleared there and then.** Read `count of documents` and `count of windows`; a popup or a document the run did not open is cleared immediately - `tell application "Keynote" to activate`, then System Events `key code 53` (Escape), `killall Keynote` only if that fails - and is never carried into the next attempt (an attempt over a standing dialog is void). The phantom panels answer 0 to `count of windows` while they sit on Chaehan's screen, so the recipe is the check, not the number alone. A stage copy is never opened by hand: a sandboxed `open` of one is refused with "can't be opened right now - Operation not permitted" and leaves exactly that popup. The deck is edited as the session deck, or against the document Chaehan already has open.

**A deck copied from the stage carries the quarantine flag and will not open until it is cleared.** `cp` of a `.key` brings `com.apple.quarantine` (and `com.apple.provenance`) along without an approving app in its field, so Keynote's `open` raises Gatekeeper's confirmation - which no Apple event can answer, so the script hangs or dies with an empty log (`xattr -l` shows `0083;...;Keynote;` on a deck Keynote has opened, `0283;...;;` on the copy). Clear it with `xattr -d com.apple.quarantine <copy>` (the pipeline's `_strip_quarantine` does it for its own copies) before the run; 2026-10-17, E08: two probe runs died inside `open` on a freshly copied deck.

**One session drives Keynote at a time; that is claimed before a run and released after it.** A run that dies inside `open` - silently, with an empty log, or as `-609 Connection is invalid` - is read as a handoff problem first: ask who else holds the app before suspecting the file, its copy, its metadata or the document's identity. `killall Keynote` is a reset only while this session owns the app; from a pass that shares the machine it takes the other pass's run down. 2026-10-17, E08 against E05: the two passes broke each other's runs for an hour ("Two opens cannot be queued against one Keynote; whichever script is second never returns") while each read the -609 as a defect in its own deck. Write the claim and the release where the other sessions read them - the session's own log, or the log the pass writes - and wait for the other's release line. Rule 166 in agentkit `RULES.md`.

Log entry in the session's `_log.md`: the instruction in the user's words, the class, what was swept, the measured result, the backups. Memory only when the state changed: the current-state bullet in `memory/kubs.md`; a new class or value goes to `agentkit/rebuild_defects.md` and `deck_reference.json` first, and memory points there.

## The failure classes this pass exists to stop

| Class | One-line trigger | Enforced by |
| --- | --- | --- |
| Reference geometry re-derived | an element that exists elsewhere in the deck is created or replaced, or inherited from the page a new page was duplicated from | the values file; the band, stroke and chart checks |
| A standing requirement dropped | a new instruction on an artifact with existing requirements | preflight 2; the chart check |
| A spec applied to one instance | "all", "every", or a scope the user can see | preflight 1; the pages check |
| Verification that cannot fail | any correctness claim | deckcheck; magnified reads |
| Source structure as the spec | a figure or page built from a book or earlier deck | preflight 3; rule 134 |
| A live element installed as a flattening | a new element the user must edit or animate (a diagram, boxes, a table), or a page composed of photographs and figures put together as one PNG | the build step's form rule; rule 104; the `flat` check (the page's own object list) |
| An install checked only where it wrote | slides added to an existing deck; the pass compares the added pages alone | Step 3.4 — the whole-deck export before the write, every page compared after it (class 7) |
| A Keynote pass that leaves the app's state behind | a hand-rolled `open` of a stage copy, or a run that ends with a popup or a stray document on Chaehan's screen | Step 4 — the state check, the Escape recipe at the first refusal, and the drop of hand-rolled opens (socrates failure 58, 2026-10-16) |
